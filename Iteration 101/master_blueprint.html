agentic crypto trading system master blueprint

00 Overview

A multi-agent, self-improving crypto trading system. Trades BTC first, one currency added at a time after. Holds positions for 10–15 minutes up to several hours — long enough to let several LLM reasoning steps sit inside the decision loop without the latency mattering.

01 Vision & Philosophy

Every decision starts from hard numbers — price, indicators, order book, ML model outputs — computed deterministically. Only after that numeric picture is locked in do any LLM-based agents get to reason over it: debate, chart-pattern reading, macro and sentiment interpretation, final decision-making. Nothing an LLM says can override or contradict the actual computed data.

Every part of the system is individually switchable through one configuration file — every data source, every analysis agent, every ML model, every LLM-based layer. Nothing requires touching code to turn off. This controls API cost, lets you test what happens with a source removed, and isolates exactly which signals are actually earning their keep.

Nothing gets to influence real trades until it has earned that right with evidence: first tested against years of historical data, then run live on paper across multiple market conditions, then formally reviewed against a fixed bar — and only after clearing all of that does it get turned on for real money, starting small.

Prove it on historical data, prove it on paper, then — and only then — let it touch real money.

02 Core Principles

  • Determinism before LLMs. All numerical data is computed first, without any LLM involvement, and locked into a snapshot. LLM agents reason on top of it; they cannot invent or override numbers.
  • Nothing trades real money until it's proven. Historical backtest → paper trading → formal evidence review → live, in that order, every time.
  • New or unproven components run in observation mode first. They generate a real opinion every cycle, get logged, get scored — but don't change the trade until they've demonstrably added value.
  • Every agent is a switch. Every data source and analytical agent can be turned off from one config file, with a defined, safe fallback downstream.
  • One coin first. Full validation on BTC before touching a second currency — only ever one thing that can be wrong while debugging.
  • Risk management is not optional. Portfolio risk limits, position sizing, and pre-trade guard checks stay on; everything else is a genuine switch.
  • Learning happens deliberately. Rule synthesis and model retraining run in controlled, reviewable batches — never silent continuous updates against open positions.

05 Master Config / Kill-Switch System

Turn any data source, agent, or subsystem on or off — to save API cost, or to deliberately test what happens with something removed — by editing one file, never by touching code. Every agent reads its own on/off state from this file at the start of every cycle.

# config/system_config.yaml  abridged
system:
  active_currency: "BTC"
  validation_stage: 1        # 1 | 2 | 3 | 4

data_sources:
  prism:    { enabled: true }   # OHLCV  core, always on
  titan:    { enabled: false }  # on-chain  off, saving API cost
  echo_sentiment:
    sources: { twitter: {enabled: false}, reddit: {enabled: true} }

intelligence_agents:
  oculus:
    enabled: true
    influences_decision: false  # observation mode until Stage 3
    timeframes: { 1m: {enabled:false}, 15m: {enabled:true}, 4h: {enabled:true} }

debate_layer:
  enabled: true
  influences_decision: false    # observation mode until Stage 3
  risk_subdebate: { enabled: true, influences_decision: true }

reinforcement_learning:
  darwinex: { enabled: false, mode: "offline_batch_only" }

risk_layer:
  sentinel: { enabled: true }
  warden:   { enabled: true }
  guardian: { enabled: true }   # these three never gate off for live trading

The rule that makes turning things off safe: a disabled input is never silently treated as neutral. Every place that fuses multiple signals renormalizes its weights around what's actually available, and flags that its evidence is reduced.

Switched off Downstream effect in ORACLE's fusion
echo_sentiment Sentiment weight dropped and redistributed; confidence report flagged as reduced evidence.
titan (on-chain) Same — weight redistributed, evidence-quality flag set.
one ML model Excluded from the ensemble vote; agreement % computed only across remaining active models.
oculus (entire) No visual read that cycle; scorecard notes "no read" rather than counting a miss.
debate_layer No debate runs; STRATEGIST proceeds on ML, technicals, sentiment and macro alone.
sentinel / warden / guardian Live trading is blocked entirely, regardless of anything else in the config.

Every decision — paper or live — is stored with a complete snapshot of exactly which agents and data sources were switched on when it was made. Without that, there's no way to later tell whether a trade lost because the strategy is bad or because sentiment happened to be off that week.

06 Risk Layer & Starting Limits

Agent Function
SENTINEL Global portfolio risk: max daily loss, max drawdown, per-currency exposure cap, correlation limits, total portfolio heat. Runs identically in paper and live so Stage 2 genuinely rehearses Stage 4.
WARDEN Position sizing via fractional Kelly: kelly = (win_rate×avg_win)/avg_loss − (1−win_rate), then fractional = kelly × 0.25, scaled by volatility and confidence tier.
GUARDIAN Sequential fail-fast guard pipeline: cooldown → symbol whitelist → max position size → daily loss stop → margin sufficiency → min risk/reward. Every rejection logged.
  • Max daily loss: 2% of capital
  • Max single-trade loss: 0.5% of capital
  • Max concurrent open positions: 4
  • Max exposure per currency: 25% of capital
  • Max total portfolio heat: 5%

These three agents are the one place the system enforces a hard rule regardless of config: it will not move into Stage 4 while any of them is switched off.

07 How the Debate Layer & OCULUS Earn Real Influence

  1. Minimum sample size and regime coverage. Scored trades must span an uptrend, a downtrend, and a ranging period before any number is trusted.
  2. The comparison. For every closed trade, reconstruct what STRATEGIST actually decided without the component, versus what it would have decided with it. Where they agree, the component added nothing that trade.
  3. Weight by outcome size, not win/loss. Score by R-multiple. A component right less than half the time but right big when it matters can still be net positive.
  4. The promotion bar is written down before results exist — beat the "without it" baseline by an agreed margin, on the divergent-trade subset, across all three regimes, over the full sample.
  5. Demotion is automatic. A promoted component keeps being scored; if it later drops below the bar, it reverts to observation mode.
  6. Check it isn't just riding the trend. Credit is given net of the period's prevailing directional bias, not raw hit rate.

The debate layer and OCULUS are scored and promoted independently of each other — one can clear the bar and the other not. The risk sub-debate is scored against sizing outcomes rather than direction, on its own timeline.

09 Build Order

The validation stages decide when you move on, not the calendar.

  1. Config / kill-switch infrastructure first — every agent reads its on/off state from this from day one. CCXT bridge in paper mode. Live BTC data flowing through PRISM-BTC.
  2. Deterministic core + Stage 1 walk-forward backtesting harness, before there's anything sophisticated to test. 2–3+ years of BTC history segmented into uptrend/downtrend/chop.
  3. ML ensemble (XGBoost + LSTM first) + full Stage 1 run against buy-and-hold and MA-crossover. Do not proceed until it passes every regime segment.
  4. Intelligence layer + OCULUS: chart rendering, the vision-LLM call, structured output, per-timeframe switches, caching.
  5. Debate layer (observation mode from line one) + ORACLE's Bayesian fusion + STRATEGIST's decision logic.
  6. GUARDIAN, WARDEN, SENTINEL, full order lifecycle — Stage 2 paper trading begins here.
  7. ARGUS, VELOX, NEMESIS, KRONOS, CASSANDRA's scorecards built alongside paper trading from its first trade. AETHER dashboard.
  8. Formal evidence review once all three regimes are covered — flip influences_decision or leave in observation.
  9. Live trading, BTC only, small and staged. RL stays off unless deliberately revisited, offline-batch only.
  10. Second currency — repeat the pipeline for ETH, then SOL, BNB, XRP, MATIC.

Stage 1 Historical Walk-Forward Backtest

Deterministic + ML core only — indicators, order-book features, the ML ensemble, sizing and risk-gate logic. The debate system and OCULUS are not tested here: both depend on live news, sentiment, and rendered chart context tied to a specific moment, which can't be faithfully reconstructed for years of history. At least 2–3 years of BTC history, split across an uptrend, a downtrend, and chop; true walk-forward (never a single in-sample fit); net of realistic fees, slippage, spread; benchmarked against buy-and-hold and MA-crossover. To pass: beat both baselines, net of costs, in every regime segment individually.

Stage 2 Live Paper Trading

The full system runs live, on paper, for as long as it takes to see a genuine uptrend, downtrend, and ranging period — not a fixed number of days. The deterministic core, ML ensemble, and confidence/decision/risk/execution layers are authoritative. The debate system and OCULUS run in observation mode: a real, logged opinion every cycle that does not change the trade.

Stage 3 Formal Evidence Review

A fixed, pre-agreed bar, decided before you look at results. Enough scored trades spanning all three regimes; comparison between what STRATEGIST actually did and what it would have done with the component included, weighted by outcome size. If a component doesn't clear the bar it stays in observation mode — never forced in "because it should theoretically help."

Stage 4 Live, Small and Staged

Real capital, starting small and scaling gradually. A second currency does not start its own Stage 1 until BTC has run in Stage 4 for a meaningful stretch without a structural failure.
